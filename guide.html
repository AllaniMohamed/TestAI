🚀 Getting Started

TestIA is an intelligent API testing and automation platform that helps you automatically generate, execute, and manage tests for your REST APIs. Whether you're a developer or a project manager, TestIA streamlines your testing workflow.

What You Can Do with TestIA

📚

Manage APIs

Register your REST APIs using Swagger/OpenAPI documentation or manually add endpoints.

🧪

Generate Tests

Automatically generate comprehensive test cases for your API endpoints.

▶️

Execute Tests

Run tests manually or on a schedule using CI/CD integration with Jenkins.

📊

Track Results

View detailed reports, success rates, and performance metrics for your APIs.

👥

Share Projects

Collaborate with developers by sharing projects with granular access control.

⚡

Quick Testing

Execute ad-hoc API tests with custom parameters and authentication.

User Roles

MANAGER

Project managers can create projects, generate tests, view reports, share projects with developers, and manage team access.

DEVELOPER

Developers can view shared projects, execute tests, and use quick API testing. They cannot create or manage projects.

🔐 Authentication & Registration

Creating an Account

  1. Visit the TestIA website and click Register
  2. Fill in your account details:
    • Full Name: Your complete name (minimum 2 characters)
    • Email: A valid email address
    • Password: At least 8 characters
    • Confirm Password: Must match the password above
    • Phone Number: Optional 10+ digit phone number
    • Company: Optional company name
  3. Click Create Account
  4. You will be redirected to a verification waiting page

Email Verification

After registration, you will receive a verification email. This email is sent to your registered email address and is valid for a limited time.

  1. Check your email inbox (including spam folder)
  2. Click the verification link in the email
  3. Your email will be marked as verified
  4. Proceed to phone verification or login
Email Not Received? If you don't receive the verification email within a few minutes, click Resend Verification Email on the verification page.

Phone Verification

Phone verification adds an extra layer of security to your account.

  1. On the phone verification page, enter the code sent to your phone
  2. The code is valid for a limited time
  3. If you don't receive the code, click Resend Phone Code
  4. After successful verification, you can log in

Logging In

  1. Go to the login page
  2. Enter your email address
  3. Enter your password
  4. Click Sign In
  5. You will be redirected to the dashboard
Remember Me: To stay logged in on this device, your session is stored securely in your browser.

Forgot Password

  1. Click Forgot Password? on the login page
  2. Enter your registered email address
  3. Click Send Reset Link
  4. Check your email for a password reset link (valid for 1 hour)
  5. Click the link and enter your new password
  6. Log in with your new password

Account Registration via Invitation

Managers can invite developers to collaborate on projects through the sharing system. When invited:

  1. You will receive an invitation email
  2. Click the link in the email
  3. Create a new account using your details
  4. You will have access to the shared project after account creation

📁 Projects & Services Management

Understanding Projects

In TestIA, a "Project" (also called a "Service") represents a single REST API that you want to test. Each project contains endpoints that are automatically discovered from your API documentation or added manually.

Viewing Your Projects

  1. Click Services in the navigation menu
  2. You will see a list of all projects you own (managers) or have access to (developers)
  3. Each project shows:
    • Project Name: The API name you gave it
    • URL: The base URL of the API
    • Status: Active or inactive indicator
    • Endpoints: Number of API endpoints
    • Success Rate: Percentage of passing tests with color coding

Searching Projects

Use the search box at the top of the projects list to filter by project name. The search works in real-time as you type.

Creating a New Project

Only managers can create new projects. Follow these steps:

Step 1: Choose Documentation Mode

You can add a project in two ways:

  • Swagger/OpenAPI: Upload API documentation from a Swagger URL or file
  • Manual: Manually add each endpoint with detailed configuration

Step 2: Fill Basic Information

Project Name Give your API a descriptive name (e.g., "User Management API").
Description Optional description of what this API does or any special notes.
Service URL The base URL of your API (e.g., https://api.example.com/v1). Must be a valid HTTP/HTTPS URL.

Step 3: Add API Documentation (Swagger Mode)

Choose how to provide your Swagger documentation:

  • From URL: Provide the direct link to your Swagger JSON file (e.g., https://api.example.com/v3/api-docs.json)
  • From File: Upload a Swagger/OpenAPI YAML or JSON file from your computer

The documentation URL must end with .json, .yaml, or .yml

Step 4: Configure Authentication

Select the authentication method your API uses:

None

API requires no authentication.

Basic Auth

Provide username and password. The system will encode these as Basic authentication headers.

API Key

Provide your API key. Specify whether it goes in the header (default) or as a query parameter.

Bearer Token

Provide a JWT or Bearer token for OAuth-based APIs.

Step 5: Manual Endpoints (Manual Mode Only)

If using Manual mode, you must define each endpoint:

  • HTTP Method: GET, POST, PUT, DELETE, or PATCH
  • Endpoint Path: e.g., /users, /users/{id}
  • Description: What this endpoint does
  • Tags: Comma-separated categories (e.g., users, auth)
  • Parameters: JSON format query/path parameters
  • Request Body: JSON Schema for POST/PUT requests
  • Response Body: JSON Schema for expected responses
  • Status Codes: Comma-separated valid HTTP status codes (e.g., 200,201,400)
  • Requires Auth: Toggle if this endpoint needs authentication
Add Multiple Endpoints Click the + Add Endpoint button to add more endpoints to your manual project.

Step 6: Save Project

Click Save Project to create your project. The system will validate all information and show any errors.

Project Created Successfully! Your project is now ready. You can start generating and executing tests immediately.

Project Details Page

Click on any project to open its details page with multiple tabs:

Tab Description
Endpoints View all API endpoints, their methods, paths, and descriptions. Generate tests for selected endpoints.
Tests View generated test cases with details, expected outcomes, and execution history.
Execution Execute tests manually. See real-time logs and results as tests run.
History View past test executions with timestamps, results, and performance metrics.
Reports Detailed analytics including success rates, performance charts, and trend analysis.
Settings Edit project details, update credentials, and configure sharing options.

▶️ Test Execution & API Testing

Running Tests for a Project

  1. Navigate to your project from the Services list
  2. Click the Execution tab
  3. You will see all endpoints for this project
  4. Click ▶️ Run Tests to start execution
  5. The system will execute all tests and show real-time logs
  6. Once complete, view detailed results including:
    • Total tests run
    • Number of passed tests
    • Number of failed tests
    • Overall success rate percentage
    • Detailed logs for each test

Understanding Test Results

✓ Passed

The API endpoint returned the expected response code and body matched the schema.

✗ Failed

The endpoint failed validation. Check the logs to see exactly what went wrong (wrong status code, invalid response format, timeout, etc.).

⚠ Warning

The test executed but encountered non-critical issues (slow response time, unexpected fields in response).

Quick API Execution

Test any API endpoint on-the-fly without creating a full project. Navigate to Quick API Execution.

Sending a Request

  1. Enter the API endpoint URL
  2. Choose the HTTP method (GET, POST, PUT, DELETE, PATCH)
  3. Add headers, query parameters, and request body as needed
  4. Configure authentication if required
  5. Click Execute

Configuring Authentication for Quick Tests

Auth Type: Select from None, Bearer Token, Basic Auth, or API Key

  • Bearer Token: Paste your JWT or Bearer token
  • Basic Auth: Enter username and password (automatically encoded)
  • API Key: Provide the key and specify header name or query parameter

Understanding the Response

After execution, you see:

  • Status Code: HTTP response status (200, 404, 500, etc.)
  • Response Headers: Metadata about the response
  • Response Body: The actual response content (JSON, XML, HTML, etc.)
  • Execution Time: How long the request took
Save Request: You can save frequently used API requests for quick access later.

Understanding Test Logs

When tests execute, detailed logs show:

[12:34:56] Starting test execution for 5 endpoints
[12:34:57] ✅ GET /users - 200 OK (145ms)
[12:34:58] ✅ GET /users/1 - 200 OK (98ms)
[12:34:59] ❌ POST /users - Expected 201 Created, got 400 Bad Request
[12:35:00] ✅ DELETE /users/1 - 204 No Content (52ms)
[12:35:01] Execution complete: 4 passed, 1 failed, 80% success rate

Each log entry includes a timestamp, status indicator, endpoint info, and the result.

👥 Project Sharing & Team Collaboration

Share projects with team members (developers) to collaborate on API testing. Managers can control what each developer can do.

Sharing a Project

  1. Open your project and click the Settings tab
  2. Find the Sharing section
  3. Click Share with Developers
  4. A modal will appear
  5. Enter the developer's email address
  6. Choose the access level:
    • Read Only: View project and results, cannot generate or execute tests
    • Read & Execute: View project, execute tests, but cannot modify project settings
  7. Click Send Invitation
Invitation Process: An invitation email will be sent to the developer. They must accept the invitation to gain access.

Managing Shares

To modify or revoke access to a shared project:

  1. Open your project and click Settings
  2. Find the Manage Shares section
  3. You will see a list of all developers this project is shared with
  4. For each developer, you can:
    • Change Access Level: Toggle between Read Only and Read & Execute
    • Revoke Access: Click the trash icon to immediately remove access

Viewing Shared Projects (For Developers)

If you are a developer and have been granted access to projects:

  1. Navigate to Shared Projects
  2. You will see all projects shared with you
  3. Each project shows the manager's name, when it was shared, and your access level
  4. Click on a shared project to:
    • View endpoints and tests
    • Execute tests (if you have Read & Execute access)
    • View reports and history
Access Restrictions: If you only have Read Only access, you cannot generate new tests or execute them. Contact the project manager to request higher access levels.

Share Status

Status Description
Pending Invitation sent but not yet accepted. Developer needs to verify email and create account.
Active Developer has accepted the invitation and has active access to the project.
Revoked Access has been removed. Developer can no longer view this project.

The reports page shows overall metrics across all your projects:

⚙️ CI/CD Automation with Jenkins

What is Jenkins Integration

Jenkins integration allows you to automatically execute your API tests on a schedule or as part of your CI/CD pipeline. Instead of manually running tests, TestIA can trigger them automatically at specified times or frequencies.

Accessing Jenkins Configuration

  1. Click Jenkins in the navigation menu
  2. You will see all your projects with Jenkins automation controls

Enabling Automation for a Project

  1. Find your project in the Jenkins page
  2. Click Configure Automation for that project
  3. A modal will appear with configuration options

Configuring Automation

Enable Automation

Toggle this switch to enable or disable automated execution for this project.

Schedule Frequency

Choose when tests should run:

  • Daily: Run every day at a specified time
  • Weekly: Run on specific days of the week
  • Monthly: Run on specific dates

Time Setting

Set the hour (0-23) and minute (0-59) when the tests should execute. Use 24-hour time format.

Example: 14:30 means 2:30 PM

Automation Status

The Jenkins page shows your projects in two sections:

  • Enabled Projects: Automation is active and tests will run on schedule
  • Disabled Projects: Automation is off or not configured

Monitoring Automated Execution

  1. Navigate to your project's History tab
  2. Automated executions will be labeled as "Automated" or "Jenkins"
  3. View detailed results just like manually executed tests
  4. Check notifications for alerts when automated runs complete
Notifications: You will receive notifications when automated test runs complete, whether they passed or failed.

Direct Jenkins Access

To manage Jenkins directly (advanced users), click the Open Jenkins button to access the Jenkins dashboard at localhost:9090.

Timezone: Automation schedules use your server's timezone. Ensure your time settings account for this when scheduling tests.

🆘 Troubleshooting & Tips

Common Issues & Solutions

Can't Log In

Problem: "Incorrect email or password" error

  • Double-check your email spelling
  • Ensure Caps Lock is off
  • If you forgot your password, use Forgot Password? on the login page
  • Verify that your email is verified (check your email inbox for verification link)

Email Verification Not Received

Problem: No verification email in inbox

  • Check your spam/junk folder
  • Wait a few minutes - emails may take time to arrive
  • On the verification page, click Resend Verification Email
  • Check if your email provider is blocking test emails
  • Verify you entered your email correctly during registration

Phone Verification Code Not Working

Problem: Code expired or incorrect

  • Codes are only valid for 5 minutes - request a new one if expired
  • Ensure you're entering the code exactly as received
  • Codes are case-sensitive if they contain letters
  • Click Resend Code to request a fresh code

Project Not Loading or Tests Failing

Problem: Project page won't load or all tests fail

  • Verify the API service URL is correct and accessible
  • Check that the authentication credentials are valid
  • Ensure the API is currently running and online
  • Check your network connection
  • Try refreshing the page (F5 or Ctrl+R)
  • Check if API has CORS headers configured to allow requests from TestIA

Test Execution Timeout

Problem: Tests take too long or timeout

  • Your API may be responding slowly - check the response time in logs
  • Verify your internet connection speed
  • Check if the API server has high load
  • Ensure no firewall is blocking connections to the API

Shared Projects Not Appearing

Problem: Can't see projects shared with me

  • Ensure your email has been verified
  • Check your email for sharing invitations
  • Accept the sharing invitation in the email
  • Try logging out and back in to refresh permissions
  • If already accepted, check Shared Projects section (not your own projects)

Jenkins Automation Not Triggering

Problem: Scheduled tests aren't running

  • Ensure automation is enabled for the project in Jenkins settings
  • Verify the schedule time is in the future
  • Check your timezone configuration
  • Confirm the Jenkins service is running
  • Check the Jenkins page for any error messages or warnings

API Authentication Issues

Problem: Tests fail with authentication errors (401, 403)

  • Verify API key, token, or credentials are correct
  • Check that credentials haven't expired (especially tokens)
  • Ensure the correct authentication type is selected
  • For Bearer tokens, ensure they include the "Bearer " prefix
  • Check API documentation for exact authentication header format

Best Practices & Tips

Tip: Organize Projects by Microservice Create separate projects for each microservice to make results easier to track and share with specific team members.
Tip: Keep Endpoints Documentation Updated Regularly update your Swagger/OpenAPI documentation to ensure tests stay current with your API changes.
Tip: Use Meaningful Names Give projects and endpoints clear, descriptive names to make reports and test results easy to understand.
Tip: Schedule Off-Peak Testing Configure Jenkins automation to run during off-peak hours to avoid impacting production API performance.
Tip: Regular Backups Periodically download reports to maintain historical records of your API quality metrics.
Tip: Review Failed Tests Promptly When tests fail, investigate immediately to identify whether it's an API issue or test configuration problem.
Tip: Rotate API Credentials Regularly Update stored API keys and tokens periodically for security. After rotating, update them in TestIA.
